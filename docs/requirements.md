# 要件: X のネタ元アカウント探しの改善

2026-10-05 に、コードを見ずに整理した結果（1段階目）。次は今のコードと突き合わせる（2段階目）。

## 目的

X のリストに入れて引用・発信するための、良いアカウントを、少数だけ・新しい人中心に・手間なく見つけたい。

今の不満:
- 数が多すぎて、全部は見られない（選ぶのにも時間がかかる）
- 毎週同じ人が出てきて、新しい人がわからない
- 発信していない人や、AI と関係ない投稿ばかりの人が混ざる
- 毎回手で実行するのが面倒

## 決めたこと（作る順）

自動化は最後。一覧の中身が良くなる前に自動化しても、良くない一覧が毎週届くだけなので。

1. **新しい人だけ**: 先週までに一覧に出た人を除く。
2. **少数に絞る**: GitHub のフォロワー数が多い順に並べ、上位 N 人だけを出す（N は既定 10、実行時に変えられる）。
3. **メジャーな AI 組織の人に印を付けて優先する**: 対象は Anthropic、OpenAI、Google DeepMind、Meta、Hugging Face、Mistral AI。判定は GitHub プロフィールの所属（company）と、その組織の公開メンバーかどうか。
4. **X で AI について発信している人だけにする**: X の API で直近20件の投稿を読み、AI に関する投稿が3件以上ある人だけを残す（発信していない人を除く）。X のフォロワー数も併記する。予算は月1,000円程度。
   - 予算を守るため、X の判定は上位 N 人だけに行う。判定で落ちた人の分は、N 人目より下の人で補充しない（一覧が N 人より少なくなってもよい）。
   - 月の読み取りは 1,600件を上限にする。超えたらその月は X の判定を止め、2・3 までの一覧だけを通知する。
5. **毎週自動で実行する**: GitHub Actions で毎週決まった時間に実行し、一覧を自分に通知する。リポジトリへのコミットや Issue にはしない（Issue は放置されて溜まるため）。
   - 通知は Discord の Webhook で自分に送る。Webhook の URL は GitHub の Secrets に `DISCORD_WEBHOOK_URL` として置く。

## 後回し（1〜5 のあとに判断する）

- **トップコントリビューターを引用している X の発信者**も候補に入れる。X の検索 API が必要で、情報源を広げる別の機能になるため。
- **X のリストへの自動追加**。最終的に人間が選ぶので、まずは一覧で十分。

## 作らないこと

- 「これから伸びそうなベンチャー」の機械的な判定。基準を数値にできない。AI 系の trending 自体がすでにその候補を拾っているので、そこに任せる。

## 置いた仮定

- 上位の人数 N は既定 10 人。「何人でもいいが、多すぎると管理と選ぶ手間が大変」という答えから。
- 「先週までに出た人」は、過去の実行結果を保存して判定する（保存先は2段階目で決める）。
- 「AI に関する投稿」は、投稿の本文にキーワード（AI、LLM、GPT、Claude、Gemini、model、agent、機械学習、生成AI など）が含まれるかで判定する。費用をかけずに始めるため。
- 4 の X の投稿の読み取り量は、月あたり 上位 N 人 × 20件 × 約4回（N=10 なら約800件）。
- X の API は従量課金を想定する。読み取り 1件 約0.005ドル（X の公式の料金で要確認）。N=10 なら月約800件で約4ドル（約600円）の見込み。
- 英語・日本語どちらの発信者でもよい。

例: 先週 alice と bob が出ていて、今週の候補が alice（フォロワー500）、carol（300）、dave（900）なら、今週の一覧は dave、carol の順になる。
