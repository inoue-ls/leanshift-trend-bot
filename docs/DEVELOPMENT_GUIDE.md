# 開発者ガイド (DEVELOPMENT_GUIDE)

本書は、`leanshift-trend-bot` のソースコードを変更したり、新しい機能を追加したりする開発メンバーのための作業手順およびコード品質ガイドです。

---

## 1. 機能追加・変更の基本手順

本プロジェクトでは、データ構造の厳格性とテスト容易性を保つため、機能追加時は必ず以下の順番（M-V-C-T）でファイルを編集します。

### ① `models.py` (データの定義)
- 変更や追加する出力結果（AIの抽出フィールドなど）がある場合は、まず `models.py` で Pydantic モデルを定義または更新します。
- **注意**: `RawArticle` などの生データ構造は外部結合のマスターモデルのため、変更不可です。新しい出力は `AnalysisCore` や `ZennDraft` などの内部エンティティを拡張します。

### ② `analyzer.py` (AIのロジック・プロンプト・抽出スキーマ)
- 定義した Pydantic モデルに沿って、Geminiに与えるシステム指示（`_BATCH_SYSTEM_PROMPT` 等）のテキストを更新します。
- **Structured Outputs の紐付け**: Gemini API の `response_schema` に渡す Pydantic 構造体（`_BatchAnalysisResponse` など）を更新し、出力結果が新しいモデルに対応するようにパーサー（`parse_batch_response`）を調整します。

### ③ `main.py` (オーケストレーターと出力)
- 更新された `analyzer.py` から返される新規フィールドを受け取り、制御フローを調整します。
- コマンドライン出力部分、および Markdown レポート出力部（`save_markdown_report`）に新規フィールドを組み込み、レンダリング出力を調整します。

### ④ `tests/` (テストコードの更新と実行)
- 変更点に関連するテストコード（`tests/test_analyzer.py`）を追加・修正します。
- `pytest` を実行し、すべてのテストがパスすることを確認します。

## 2. 品質チェックとテスト実行コマンド

本プロジェクトでは、コミット前または作業完了前に以下のチェックを「エラーが0件」になるまで実行することが憲法（[CLAUDE.md](file:///home/saishin/gtd/03_projects/leanshift-trend-bot/CLAUDE.md)）で定められています。

### 静的型チェック (mypy)
Pydantic の型定義に不整合がないかをチェックします。
```bash
python3 -m mypy .
```
- ※ 型エラーが1件でもある状態でのコミットやプルリクエストは不可とします。

### 単体テスト (pytest)
AIパーサーなどのコアロジックを検証します。
```bash
python3 -m pytest -v
```

## 3. `.antigravityignore` の運用ルール

リポジトリルートにある `.antigravityignore` は、自動自律型エージェントである **Antigravity** が編集・作成できないファイルを定義する防護柵（ガードレール）です。

### 設定内容
```text
# PythonのソースコードとテストはAntigravityに触らせない
*.py
tests/
__pycache__/
.mypy_cache/
.pytest_cache/
.env
```

### 運用ルール
- **プログラムの安全性保護**: Python ソースコード（`*.py`）やテストコード（`tests/`）、環境設定ファイル（`.env`）はエージェントによって直接書き換えられないようになっています。
- **ドキュメントの編集権限**: `docs/` ディレクトリ内のドキュメントや設計書、プロジェクトルートの `README.md`、`my_status.txt` などのドキュメント・設定ファイルのみ、エージェント（Antigravity）による直接の書き込み・変更が許可されています。
- **追加の保護**: 新たな一時キャッシュフォルダやPythonファイル用モジュールを追加した際は、必ず `.antigravityignore` に追記してください。

## 4. 二刀流エージェント（Claude Code / Antigravity）の役割分担

本リポジトリの開発では、特性の異なる2つの自律型AIエージェントを使い分け、役割を分担させることで安全かつ最速の開発を実現しています。

```
                   ┌──────────────────────────────────┐
                   │    Human Developer (人間)        │
                   └─────────────────┬────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
┌─────────────────────────────┐                     ┌─────────────────────────────┐
│      Claude Code            │                     │      Antigravity            │
│  (システム実装・テスト・実行)   │                     │  (設計・プロンプト・ドキュメント)│
└──────────┬──────────────────┘                     └──────────┬──────────────────┘
           │                                                   │
     [ 触れる領域 ]                                      [ 触れる領域 ]
    ・*.py (プログラムコード)                           ・docs/ (設計ドキュメント)
    ・tests/ (単体テストコード)                         ・README.md (概要説明)
    ・shell (pytest/mypy/git等の実行)                  ・Prompt Templates (AI指示文)
```

| 特性 / 役割 | Claude Code (実装特化) | Antigravity (設計・プロンプト特化) |
| :--- | :--- | :--- |
| **主な役割** | ソースコードの実装、リファクタリング、テストの記述、コマンドの実行・検証、バグ修正。 | システム設計書の作成、アルゴリズムの定義、Gemini向けシステムプロンプトの設計、Few-Shotデータの作成。 |
| **編集ファイル** | `*.py` / `tests/*.py` / `scripts/*.sh` | `docs/*.md` / `README.md` / `my_status.txt` |
| **得意領域** | Pythonの実行、静的検証エラーの解消、テストファーストでのロジックの記述。 | 高度な日本語プロンプトエンジニアリング、構造化ドキュメント作成、コスト計算・性能比較。 |
| **強み** | 実際に動くコードの検証とデバッグ能力。 | ガードレールに守られた安全な設計策定と人間への論理的説明力。 |
